
ДОПОЛНИТЕЛЬНОЕ ЗАДАНИЕ: КЛАССИФИКАЦИЯ ЗАДАЧИ

Если информации достаточно для формирования SUMMARY и TITLE, после всего основного ответа добавь технический блок:

[AI_TAGS]
{"type":"<значение или null>","products":["<значение>"],"objects":["<значение>"],"object_names":[{"type":"<вид объекта>","name":"<точное наименование>"}]}
[/AI_TAGS]

Если по правилам основного промпта нужно вывести INSUFFICIENT_INFORMATION, выведи только INSUFFICIENT_INFORMATION и не добавляй блок AI_TAGS.

Выбери ровно один type из списка:

- `консультация` — анализ, объяснение, рекомендации или ответы без изменения системы;
- `разработка` — создание или изменение кода, отчетов, обработок, печатных форм, расширений или обменов;
- `обновление` — установка релиза или обновление конфигурации, платформы, расширения или компонента;
- `координация` — звонки, созвоны, встречи, согласование, передача информации, организация или контроль работ, когда собственные технические работы не являются основным результатом.

type определяй по основному фактически выполненному результату, а не по первоначальной формулировке клиента. Если type нельзя определить доказательно, верни null.

Выбери один или несколько products только из переданного ниже списка. Указывай продукт только при прямом подтверждении в контексте. Не определяй продукт по догадке. Если продукт нельзя определить, верни пустой массив.

В справочнике `product_normalization` ключ — это каноническое значение product, а массив — варианты его упоминания. Если в контексте встретился любой вариант, верни в `products` соответствующий канонический ключ. Сопоставляй без учета регистра. Никогда не возвращай сам алиас вместо канонического ключа.

КЛАССИФИКАЦИЯ ОБЪЕКТОВ РАБОТЫ

Определи объекты, которые были непосредственным предметом выполненной работы или консультации, только если можно достоверно определить их конкретное наименование. Верни массив objects из разрешённых значений справочника:
- отчет — отчёты, включая внешние отчёты и отчёты на СКД;
- расширение — расширения конфигурации 1С;
- регистр — регистры сведений, накопления, бухгалтерии и расчёта;
- документ — документы как объекты 1С;
- обработка — обработки, включая внешние;
- справочник — справочники как объекты 1С;
- печатная форма — печатные формы документов и других объектов;
- обмен — обмен данными между базами или системами, синхронизация, правила обмена, загрузка и выгрузка в рамках такого обмена.

Правила выбора objects:
1. Обязательное условие: конкретное наименование явно подтверждено исходными материалами. Без имени не добавляй объект ни в objects, ни в object_names. Выбирай объект, если его создавали, дорабатывали, настраивали, обновляли, диагностировали, исправляли связанную с ним проблему или консультировали по его использованию. Опирайся на подтверждённые действия и результаты.
2. Не добавляй объект только из-за упоминания в постановке, переписке, скриншоте или ошибке. Если его использовали лишь как инструмент проверки, это не объект работы.
3. Можно выбрать несколько значений без повторений. Каждое должно иметь самостоятельное подтверждение.
4. Не делай технических предположений: доработка отчёта не означает изменение регистра; доработка конфигурации не означает использование расширения; загрузка файла сама по себе не означает обмен.
5. Печатная форма документа → «печатная форма». «документ» добавляй только при подтверждённой работе с самим документом, его реквизитами, формой или проведением. Внешний отчёт → «отчет», а не «обработка». Отчёт, изменённый в расширении → «отчет» и «расширение», если изменение расширения подтверждено. Обычный файл, договор или инструкция не являются объектом «документ» в этой классификации.
6. Используй только канонические значения objects в нижнем регистре из справочника. Названия конкретных объектов передавай отдельно в object_names.
7. Если вид или конкретное имя объекта не подтверждены либо подходящего вида нет в справочнике, пропусти этот объект. Если подходящих объектов нет, верни objects: [] и object_names: []. Не угадывай.

Примеры (каждый результат содержит objects и object_names):
- Исправили расчёт колонки внешнего отчёта, имя не указано → {"objects":[],"object_names":[]}.
- Обновили расширение ЭЛРОС_Доработки → {"objects":["расширение"],"object_names":[{"type":"расширение","name":"ЭЛРОС_Доработки"}]}.
- Исправили правила синхронизации ЗУП и БП, название обмена не указано → {"objects":[],"object_names":[]}. Не составляй имя обмена из названий продуктов.
- Исправили печатную форму «УПД» → {"objects":["печатная форма"],"object_names":[{"type":"печатная форма","name":"УПД"}]}.
- Изменили документ СчетНаОплату в расширении без указанного имени → {"objects":["документ"],"object_names":[{"type":"документ","name":"СчетНаОплату"}]}.
- Использовали отчёт ОСВ только для проверки другой работы → {"objects":[],"object_names":[]}.

НАИМЕНОВАНИЯ ОБЪЕКТОВ

Если у выбранного объекта явно указано конкретное наименование, обязательно добавь его в object_names как {"type":"<значение из objects>","name":"<наименование>"}. В objects перечисли только виды объектов с подтверждёнными именами из object_names. Сам по себе вид объекта не создаёт тег. Для нескольких объектов одного вида добавь отдельную запись для каждого имени.

- Используй только имя, явно подтверждённое исходными материалами и относящееся к предмету работы или консультации, а не к случайному упоминанию или инструменту проверки.
- Сохраняй написание, регистр, пробелы и подчёркивания: СчетНаОплату, ЭЛРОС_Доработки. Не превращай «Счёт на оплату» в «СчетНаОплату», если техническое имя не указано.
- Если для одного объекта явно указаны и техническое имя, и пользовательское название, предпочти техническое имя. Не создавай два тега для двух названий одного объекта.
- В name указывай только имя, без вида объекта, префикса object: и внешних кавычек. Кавычки внутри имени экранируй по правилам JSON.
- Не включай номера и даты экземпляров документов, имена клиентов, версии расширений и полный текст ошибки.
- Не придумывай имена из типовой конфигурации или общих знаний. Если имени нет или оно неоднозначно, пропусти объект целиком. Если подтверждённых имён нет, верни objects: [] и object_names: [].

Пример: доработали документ СчетНаОплату в расширении ЭЛРОС_Доработки, оба имени явно приведены в материалах:
"objects": ["документ", "расширение"],
"object_names": [
  {"type": "документ", "name": "СчетНаОплату"},
  {"type": "расширение", "name": "ЭЛРОС_Доработки"}
]
