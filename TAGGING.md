# Теги type, product и object

При закрытии задачи Gemma по-прежнему формирует `SUMMARY` и `TITLE` по исходному промпту. К этому же запросу добавляются инструкции из `task-tagging.md`.

Справочник разрешенных значений находится в `task-taxonomy.json`.

Варианты названий конфигураций и их приведение к каноническим тегам заданы в `product_normalization` файла `task-taxonomy.json`.

## Что записывается

Пример:

```text
type:консультация
product:зуп
product:бп
object:документ_СчетНаОплату
```

Тег `type:` может быть только один. Тегов `product:` и `object:` может быть несколько. Другие, в том числе ручные, теги задачи сохраняются.

Если Gemma не смогла доказательно определить категорию, существующие управляемые теги этой категории не удаляются.

## Настройки

```env
TASK_TAGGING_ENABLED=true
TASK_TAG_FIELD_NAME=tags
```

- `TASK_TAGGING_ENABLED=false` полностью отключает добавление инструкций и запись тегов.
- `TASK_TAG_FIELD_NAME` — имя поля в API-адаптере. По умолчанию используется `tags`.

## Безопасная проверка

В уже работающем сервисе откройте:

```text
/ai-test
```

Режим preview вызывает Gemma, но не пишет комментарий, SUMMARY или теги в задачу. Страница показывает теги AI и итоговый набор тегов.

API работает асинхронно:
- `POST /ai-preview?taskId=<ID>` сразу возвращает HTTP 202 с `job_id` и `status: "running"`. GET сохранён как альтернативный запуск.
- `GET /ai-preview/status?jobId=<job_id>` возвращает `running`, `completed` с полем `result` или `failed` с полем `error`.
- Повторный запуск той же задачи во время анализа возвращает существующий job_id. Одновременно допускаются две проверки; превышение лимита возвращает 429.
- Общий лимит анализа — 180 секунд, бюджет медиа — 45 секунд. Если медиа не успели обработаться, анализ продолжается по доступным данным с предупреждением.
- Результаты хранятся в памяти одного процесса до 10 минут, максимум 20 записей. Перезапуск их удаляет; отсутствующий результат возвращает 404. Для нескольких экземпляров сервиса требуется общее хранилище заданий или привязка запросов к одному экземпляру.

В поле `result` завершённого задания проверьте:

```json
{
  "tag_classification": {
    "found": true,
    "type": "консультация",
    "products": ["зуп"],
    "objects": ["отчет"],
    "object_names": [{"type": "отчет", "name": "АнализЗарплаты"}]
  },
  "task_tags": ["type:консультация", "product:зуп", "object:отчет_АнализЗарплаты"],
  "task_tags_would_be_updated": true
}
```

После проверки preview можно закрыть отдельную тестовую задачу и убедиться, что теги добавились в Bitrix24.

## Защита от повторного запуска

Обновление тегов само вызывает `ONTASKUPDATE`. `server.js` запоминает свои обновления на 10 минут и не запускает повторный анализ для такого события.

## Объекты работы

Справочник `objects` содержит: `отчет`, `расширение`, `регистр`, `документ`, `обработка`, `справочник`, `печатная форма`, `обмен`, `роль`. AI выбирает только объекты с подтверждённым конкретным наименованием; случайные упоминания и инструменты проверки не учитываются.

Непустой проверенный список `object_names` заменяет прежние теги `object:`. При отсутствии корректных имён новые объектные теги не создаются; прежние теги этой категории сохраняются. Список `objects` без имён не используется для генерации тегов. Ручные теги без управляемых префиксов сохраняются. В `/ai-test` новые теги отображаются вместе с `type:` и `product:`.

## Имена объектов

Если точное техническое имя явно указано в исходных материалах, AI возвращает его отдельно в `object_names`:

```json
{
  "objects": ["документ", "расширение"],
  "object_names": [
    {"type": "документ", "name": "СчетНаОплату"},
    {"type": "расширение", "name": "ЭЛРОС_Доработки"}
  ]
}
```

Создаются только теги с конкретными именами:

```text
object:документ_СчетНаОплату
object:расширение_ЭЛРОС_Доработки
```

Вид объекта остаётся в нижнем регистре; написание имени сохраняется. Без подтверждённого имени новый тег не создаётся. Старые ответы с одним списком `objects` не создают объектных тегов. Непустой проверенный список имён заменяет всю категорию `object:`; если имён нет, прежние теги сохраняются. Массовое удаление старых общих тегов не выполняется. `/ai-test` показывает только сгенерированные именные теги, а в итоговом наборе — также сохраняемые прежние теги.

## Единый формат и выбор продукта

Новые объектные теги имеют формат `object:вид_ТехническоеИмя`, например `object:роль_РольOData`. Код принимает имена из букв, цифр и подчёркиваний, начинающиеся с буквы или подчёркивания. Пробелы и пунктуация не удаляются автоматически: такое имя отклоняется. Подтверждение того, что это именно техническое имя, возложено на промпт; одна проверка формата не доказывает его существование.

Пользовательские названия и описания вроде «выплата зарплаты сотрудникам» не создают теги. Если имён нет, прежние объектные теги сохраняются; массовой миграции старых тегов нет. При новой непустой классификации категория `object:` заменяется тегами нового формата.

По согласованному правилу проекта АУСН как предмет работы или консультации означает `product:бп`. `product:1с-отчетность` выбирается только при подтверждённой работе с самим сервисом, а не по упоминанию налоговой, отчётов или АУСН. Правило реализовано в промпте классификации.

## Запись тегов после Task_Title

Пользовательское поле Task_Title в коде соответствует `UF_TASK_TITLE` (ответ API также может содержать `ufTaskTitle`). Новый порядок: сохранить непустой TITLE, перечитать задачу и только затем записать теги через `PATCH /v1/tasks/:id` с полем `tags`. При ошибке сохранения, пустом поле или изменившемся за время анализа TITLE запись тегов пропускается.

Событие `ONTASKUPDATE` с изменением `UF_TASK_TITLE` в пакете истории запускает отдельную фоновую классификацию по сохранённому полю, тексту задачи и комментариям. Она не меняет Task_Title, SUMMARY и комментарии и не загружает медиа. Очистка поля не запускает AI и не удаляет прежние теги. Ограничение выполнения — 180 секунд; результат доступен в `lastTaskTitleTags` на `/debug`.

Одновременные события одной задачи объединяются. После успешной обработки того же TITLE повторная классификация пропускается в течение 10 минут (кэш в памяти, сбрасывается при перезапуске). Запись тегов не запускает эту ветку, поскольку она реагирует на изменение TITLE. Событие собственного сохранения TITLE ожидает окончания обработки закрытия и использует кэш уже применённого результата. Ошибки не кэшируются как успех; повторное событие может повторить попытку.

Preview остаётся без записи в задачу: показывает, какие теги были бы применены после сохранения сгенерированного TITLE. Развёртывание само по себе не запускает обработку старых задач.
