# Теги type и product

При закрытии задачи Gemma по-прежнему формирует `SUMMARY` и `TITLE` по исходному промпту. К этому же запросу добавляются инструкции из `task-tagging.md`.

Справочник разрешенных значений находится в `task-taxonomy.json`.

Варианты названий конфигураций и их приведение к каноническим тегам заданы в `product_normalization` файла `task-taxonomy.json`.

## Что записывается

Пример:

```text
type:консультация
product:зуп
product:бп
```

Тег `type:` может быть только один. Тегов `product:` может быть несколько. Другие, в том числе ручные, теги задачи сохраняются.

Если Gemma не смогла доказательно определить категорию, существующие управляемые теги этой категории не удаляются.

## Настройки

```env
TASK_TAGGING_ENABLED=true
TASK_TAG_FIELD_NAME=tags
```

- `TASK_TAGGING_ENABLED=false` полностью отключает добавление инструкций и запись тегов.
- `TASK_TAG_FIELD_NAME` — имя поля в API-адаптере. По умолчанию используется `tags`.

## Безопасная проверка

В уже работающем сервисе откройте:

```text
/ai-preview?taskId=<ID закрытой тестовой задачи>
```

Режим preview вызывает Gemma, но не пишет комментарий, SUMMARY или теги в задачу. В JSON-ответе проверьте:

```json
{
  "tag_classification": {
    "found": true,
    "type": "консультация",
    "products": ["зуп"]
  },
  "task_tags": ["type:консультация", "product:зуп"],
  "task_tags_would_be_updated": true
}
```

После проверки preview можно закрыть отдельную тестовую задачу и убедиться, что теги добавились в Bitrix24.

## Защита от повторного запуска

Обновление тегов само вызывает `ONTASKUPDATE`. `server.js` запоминает свои обновления на 10 минут и не запускает повторный анализ для такого события.
